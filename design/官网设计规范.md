## 一、设计策略：为什么用「深色 + 双主题」

本次设计最大的约束不是版式，而是**两款游戏的美术基因几乎互斥**：

| | 字斗 | 开局一块烂木筏 |
|---|---|---|
| 基调 | 宣纸米白、淡墨远山 | 亮青蓝海水、饱和高光 |
| 主体 | 朱红毛笔字、墨迹飞白 | 低多边形木筏、卡通鲨鱼 |
| 情绪 | 沉静、对弈、东方 | 轻快、明亮、治愈 |
| 色温 | 暖（米白 + 朱红） | 冷（青蓝 + 木黄） |

如果把两张封面直接放在同一个白底页面上，页面会变成「两套互不相关的美术拼贴」。三种解法与取舍：

**方案 A：深色统一基底 + 每款游戏独立章节主题色（采用）**
页面底色压到近墨黑（#0A0B0D），让两张高饱和封面成为页面上唯一的强色源；每个游戏区块只用**一个强调色**（字斗=朱砂红，木筏=海蓝）局部染色，两者隔着深色底不直接碰撞。深底同时把封面的高光「点亮」，是最能衬游戏美术的做法，也是 Steam / TapTap 商店页的通用范式。

**方案 B：宣纸明亮风** —— 会强迫木筏的卡通蓝去适配米白，需要给蓝加灰调，等于让游戏美术迁就官网，长期看会随游戏增多而崩坏。舍弃。

**方案 C：中性极简** —— 安全但无记忆点，作为「厂商官方门面」缺少气质。舍弃。

## 二、设计系统（Design Tokens）

### 2.1 色彩

**基底与文字**

| Token | 色值 | 用途 | 对比度（对 #0A0B0D） |
|---|---|---|---|
| `--bg` | `#0A0B0D` | 页面底色（近墨黑，带极轻微暖意） | — |
| `--surface` | `#14171D` | 卡片、封面容器 | — |
| `--line` | `rgba(255,255,255,.09)` | 1px 分隔线、卡片描边 | — |
| `--ink` | `#EDE8E0` | 正文与标题（宣纸白，非纯白，减少刺眼） | **15.4:1** ✅ AAA |
| `--ink-2` | `#A9A39A` | 次级说明文字 | **7.7:1** ✅ AA |
| `--ink-3` | `#7A7570` | 仅限大字号/图标/装饰线 | 3.9:1 ⚠️ 不可用于正文 |

**双主题强调色**

| Token | 色值 | 对应游戏 | 用途 | 对比度 |
|---|---|---|---|---|
| `--seal` | `#C03A2E` | 字斗（朱砂） | 大标题字、徽章、区块装饰 | 3.6:1（仅限 ≥24px 或非文本元素） |
| `--seal-soft` | `#E4675A` | 字斗 | **小字号链接/标签**（此色才达正文标准） | **6.0:1** ✅ AA |
| `--sea` | `#35C6E8` | 木筏（海蓝） | 大标题字、徽章、区块装饰 | **9.0:1** ✅ AAA |
| `--sea-soft` | `#7FE0F3` | 木筏 | 悬停态、焦点环 | 12.4:1 ✅ AAA |

> 关键规则：**朱砂红不能用于 18px 以下正文**，正文场景一律降到 `--seal-soft`。这是双主题深色站最容易踩的坑。

**语义色**：成功 `#3FB950` / 警告 `#E3B341` / 错误 `#F85149`，仅用于状态徽章与表单反馈；状态**永不只用颜色表达**，必须配文字或图标。

### 2.2 字体

只使用两组字族，避免风格打架：

- **标题族（衬线）**：`"Noto Serif SC", "Source Han Serif SC", "Songti SC", serif`
  用于 H1/H2 与「字斗」区块，承接水墨气质。系统字体兜底，不加载外部字体文件（省 200KB+）。
- **正文族（黑体）**：`"Inter", "PingFang SC", "HarmonyOS Sans SC", system-ui, sans-serif`
  用于正文、按钮、标签。

**字号刻度（8px 基线，clamp 流式，320→1440 无级缩放）**

| 层级 | 尺寸 | 行高 | 用途 |
|---|---|---|---|
| Display | `clamp(34px, 7vw, 60px)` | 1.12 | 首屏主标题 |
| H2 | `clamp(24px, 4.2vw, 38px)` | 1.25 | 区块标题 |
| H3 | `clamp(19px, 2.4vw, 24px)` | 1.35 | 游戏名 |
| Body-L | 17px | 1.7 | 首屏副文案 |
| Body | 16px | 1.7 | 正文（移动端最小不低于 16px，避免 iOS 自动缩放） |
| Small | 14px | 1.55 | 标签、注释 |
| Micro | 12px | 1.4 | 徽章，`letter-spacing: .08em` |

### 2.3 间距、圆角、层级

- 间距严格取 **8px 倍数**：`4 / 8 / 12 / 16 / 24 / 32 / 48 / 64 / 96 / 128`
- 区块纵向留白：移动端 `padding: 72px 20px`，≥992px 提升到 `112px 32px`
- 圆角：卡片 `20px`、封面 `16px`、按钮 `999px`（胶囊）、徽章 `6px`
- 阴影克制：深色站不用大投影，改用**低透明度强调色外发光**（如 `0 24px 80px -24px rgba(192,58,46,.45)`）

## 三、断点与栅格（移动优先）

从 **320px** 最小屏起步，逐级增强：

| 断点 | 目标设备 | 布局行为 |
|---|---|---|
| 320–575 | 小手机 | 单列；封面 1:1 居中；导航折叠为「菜单」抽屉；字号取下限 |
| 576–767 | 大手机 | 单列；游戏卡封面左图右文比例 4:3；标签换行 |
| 768–991 | 平板/横屏手机 | 游戏区块改为 **左右 5:7 双栏**；导航全展开 |
| 992–1199 | 笔记本 | 内容容器 960px；首屏双封面开始倾斜悬浮 |
| ≥1200 | 桌面 | 容器 1160px；游戏区块 6:6 双栏 + 交替左右 |

页面结构用 **CSS Grid**，组件内部用 **Flexbox**；作品区若将来超过 3 款，用 `grid-template-columns: repeat(auto-fit, minmax(300px, 1fr))` 免媒体查询自适应。

## 四、信息架构

```
单页滚动
├─ 01 顶部导航（sticky，滚动后加毛玻璃底 + 描边）
├─ 02 首屏 Hero
│   ├─ 品牌名 + 一句话定位
│   ├─ 双 CTA：进入 TaTap 厂商页 / 浏览作品
│   └─ 视觉：两款封面错位悬浮（朱红 & 海蓝各一团光晕）
├─ 03 作品 Works（核心区）
│   ├─ 字斗（朱砂主题章）
│   ├─ 开局一块烂木筏（海蓝主题章）
│   └─ 敬请期待卡（虚线占位 + 订阅引导）
├─ 04 关于 About（3 条制作理念）
├─ 05 联系 Contact（TaTap / 邮箱 / 合作）
└─ 06 页脚（版权、托管说明、回到顶部）
```

**导航策略**：单页站只有 3 个锚点（作品 / 关于 / 联系），不做汉堡菜单以外的复杂导航；移动端汉堡展开为全屏抽屉，点击即滚动并自动关闭。

## 五、区块级设计要点

### 5.1 首屏（Hero）

- 左侧文案：eyebrow「TAPTAP 游戏研发工作室」→ H1「把一句规则，做成一个晚上」→ 副文案说明唯一卖点：只做小游戏。
- 右侧视觉：两张封面**错位倾斜**（-6° / +5°），各自背后一团高斯光晕（朱红 / 海蓝），建立「两款游戏 = 两种世界」的第一印象。
- 移动端：视觉移到文案下方，倾斜角度减半，防止在窄屏被裁切。
- 底部加一条细滚动提示，降低「不知道下面还有内容」的跳出率。

### 5.2 作品区（双主题章节）

每款游戏是一个**独立染色章节**，结构一致但气质不同：

| 元素 | 字斗 | 木筏 |
|---|---|---|
| 强调色 | 朱砂 `#C03A2E` | 海蓝 `#35C6E8` |
| 标题字族 | 衬线（衬出水墨味） | 黑体粗（衬出卡通告白感） |
| 区块装饰 | 一道斜向墨迹渐隐条 | 底部波浪 SVG 曲线 |
| 封面交互 | hover 时墨迹扩散、轻微放大 | hover 时封面轻浮 + 水面反光 |

卡片固定包含：**序号（01/02）→ 游戏名 → 一句话标语 → 2–3 行简介 → 标签组 → 状态徽章 → CTA**。
状态徽章（已上线 / 打磨中）用「文字 + 色点」，不依赖单一颜色。

### 5.3 敬请期待卡

虚线描边空卡，标题「第三块拼图」，说明「正在打磨中」，配一个指向 TaTap 厂商页的次级按钮「上线第一时间通知我」。
作用是把「只有两款」的劣势转成**连载感**，而不是让页面显得空。

### 5.4 关于区

三条理念，编号大字 + 短句，不加长段落：
1. **规则先能一句话讲清** — 讲不清就不做。
2. **手感优先于特效** — 先能玩，再好看。
3. **克制地更新** — 一次只改一个地方。

### 5.5 联系与页脚

- 三个入口并列：TaTap 厂商主页（主）、反馈邮箱、商务合作。
- 页脚：`© 2026 Agent 工作室` + 「本站由 GitHub Pages 托管」+ 返回顶部。
- 中国大陆上线若绑定自有域名，需在页脚补备案号（占位已留）。

## 六、微交互参数表

| 交互 | 触发 | 参数 | 实现要点 |
|---|---|---|---|
| 按钮悬停 | hover | `scale(1.02)`，200ms `ease-out` | 只动 transform |
| 按钮按下 | active | `scale(0.97)`，120ms | 给予物理反馈 |
| 封面卡悬停 | hover | `translateY(-6px)` + 光晕 `opacity 0 → 1`，260ms | 桌面端附加指针跟随光斑 |
| 卡片进入视口 | IntersectionObserver | `opacity 0→1`、`translateY(18px→0)`，600ms，stagger 90ms | 只触发一次 |
| 导航滚动 | scrollY > 24 | 背景 `rgba(10,11,13,.72)` + `backdrop-filter: blur(12px)` + 下描边 | 用 class 切换 |
| 焦点环 | `:focus-visible` | `outline: 2px solid var(--sea)`，`offset: 3px` | 禁止移除 outline |
| 木筏浮动 | 常驻 | `translateY ±4px`，6s 无限循环 | 极低振幅，不干扰阅读 |

**硬性约束**：仅动画 `transform` / `opacity` / `filter`；全部动效在 `prefers-reduced-motion: reduce` 下降级为无动画；指针跟随光斑仅在 `(pointer: fine)` + 桌面宽度下启用。

## 七、无障碍检查清单（WCAG 2.2 AA）

- [x] 正文对比度 ≥ 4.5:1，大字/图形 ≥ 3:1（见 2.1 实测值）
- [x] 朱砂红仅用于 ≥24px 标题或非文本元素，小字改用 `--seal-soft`
- [x] 语义化结构：`header / nav / main / section / article / footer`，标题层级 h1→h2→h3 不跳级
- [x] 首屏提供「跳到主要内容」skip link
- [x] 全部交互可键盘到达，`:focus-visible` 焦点环清晰可见

- [x] 状态徽章「文字 + 色点」双编码，不单靠颜色

- [x] `prefers-reduced-motion` 下关闭所有位移与循环动效
- [x] `lang="zh-CN"`、`meta viewport` 不禁止缩放

## 八、性能与部署

- **零依赖**：单文件 HTML + 内联 CSS/JS，不引入框架与 CDN，首屏 JS 约 2KB。
- **字体**：只用系统字体栈，无外部字体请求（中文字体包 3–8MB，是静态站最大性能杀手）。
- **图片**：封面用 `<img loading="lazy" decoding="async">`，非首屏资源延后加载；建议上线前把 PNG 转 WebP（体积可降 60%），并补 2x 尺寸。
- **部署**：仓库根目录放 `index.html` + `assets/` + `.nojekyll`，Settings → Pages → Source 选 `main / (root)`。
- **自定义域名**：加 `CNAME` 文件写入域名，DNS 配 4 条 A 记录或 1 条 CNAME。

## 十、可扩展性

将来新增游戏时，只需复制一个 `<article class="game game--{name}">` 区块，并在 `:root` 里加一个强调色 token：

```css
--accent-3: #B08CFF;   /* 新游戏主色 */
```

区块标题、装饰线与光晕会自动继承变量，无需改结构。若游戏增至 5 款以上，建议把作品区从「全宽交替章节」改为「双列卡片网格」，单页仍可承载。

## 十一、v1.1 修订：接入真实 Logo 后的品牌体系

> v1.1 变更摘要：品牌主色由「朱砂红」改为「Logo 紫」；首屏与关于区文案改为「一个人 + AI」叙事；新增 Logo 双版本规范。

### 11.1 为什么换色

原方案把朱砂红 `#C03A2E` 当作品牌主色，是因为当时没有 Logo，只能借用《字斗》的气质。真实 Logo 是**墨蓝黑 + 紫**的双色标记（`#1E2530` / `#7645AE`），此时若继续用红色做品牌色，会出现「Logo 是紫的、按钮是红的」的识别分裂。

修订后的色彩分工：

| 层级 | 颜色 | 用在哪 |
|---|---|---|
| **品牌色** | 紫 `#7645AE` | 主按钮、强调文字、眉题圆点、焦点环、档案卡、页脚 |
| 品牌浅紫（文字用） | `#A87BD9` | 小字号强调（6.0:1 ✅ AA） |
| 品牌亮紫（交互用） | `#C9A6EE` | 悬停、焦点环 |
| **《字斗》章节色** | 朱砂 `#C03A2E` | 只出现在「字斗」区块内 |
| **《木筏》章节色** | 海蓝 `#35C6E8` | 只出现在「木筏」区块内 |

关键原则：**品牌色管全局 UI，章节色管各自区块**。红色不再是品牌的一部分，而是《字斗》这件作品的包装色——以后加《木筏》以外的游戏，也不会和品牌撞色。

> 对比度实测：紫 `#7645AE` 对深底仅 2.8:1，**只能做填充和大面积色块，绝不能用于文字**；文字一律用 `#A87BD9`。

### 11.2 Logo 双版本规范

Logo 原稿是**白底双色**（墨蓝鸟 + 紫 A），直接放在深色站上会出现一块刺眼的白方块。因此建立两套资产：

| 文件 | 形态 | 用途 |
|---|---|---|
| `assets/logo.png` | 原版，白底，已裁切留白 | favicon、`og:image`、浅色底物料 |
| `assets/logo-dark.png` | 深底版：白底转透明，墨蓝→雾紫白 `#E9E5F2`，紫→亮紫 `#B98CE8` | 站内导航、关于区档案卡 |

**使用规则**

- **最小尺寸**：24px。低于此值鸟头细节糊成一团，改用纯文字字标。
- **安全留白**：四周至少留 Logo 高度的 25%，不贴边、不加描边、不加阴影叠加。
- **禁止**：拉伸变形、改色（除上述两版）、加投影以外的滤镜、在花哨背景上直接放（需先垫纯色底）。
- **深底版不是新 Logo**：它只是同一标记的深色适配，形状与比例必须与原件完全一致，不得单独再创作。

本站用法：导航 36px（配 `drop-shadow` 紫色微光）、关于区档案卡 104px，均使用深底版。

### 11.3 文案策略调整

原首屏「把一句规则，做成一个晚上」是一句**作品气质**描述，但它可以属于任何一家小游戏工作室。厂商简介里那句「一个人，到底能用 AI 做出多少款游戏？」才是这家工作室**唯一不可替代**的东西——它同时传达了：独立、AI 原生、产能悬念。

因此首屏改为：

> **一个人，能用 AI 做出多少款游戏？**
> 我是 Agent 工作室的"唯一员工"。没有庞大的团队，没有巨额的融资，只有无尽的脑洞和一堆极其好用的 AI 工具——我负责天马行空，AI 负责帮我搬砖。

关于区则把「小团队」升级为**档案卡**：Logo + Agent + 「唯一员工 · 创始人 · 搬砖指挥」+ 三行元数据（在职人数 1 人 / 合作对象 若干 AI / 当前状态 持续搬砖中）。自嘲式幽默与文案语气一致，也让「只有一个人」从劣势变成记忆点。

三条理念同步改写为：创意归我，搬砖归 AI / 规则先能一句话讲清 / 手感必须自己调。

## 十二、v1.2 图片策略修订

接入 1536×1536 / 1920×1920 源图后，图片方案从「小图徽章式摆放」升级为标准响应式图片：

**格式与尺寸**

| 文件 | 尺寸 | 体积 | 用途 |
|---|---|---|---|
| `zidou.webp` | 640×640 | 21 KB | 首选（覆盖 252px 显示 × @2x = 504px 需求） |
| `zidou.jpg` | 640×640 | 44 KB | 不支持 WebP 时的回退 |
| `raft.webp` | 640×640 | 34 KB | 同上 |
| `raft.jpg` | 640×640 | 55 KB | 同上 |
| `*-source.jpg` | 1536 / 1920 | 300 KB | 留档，页面不引用 |

**实现要点**

1. 用 `<picture>` + `<source type="image/webp">` 做格式降级，避免为省体积牺牲兼容性。
2. 必写 `width` / `height` 属性（640×640），浏览器据此预留空间，避免图片加载完成时的布局跳动（CLS）。
3. 首屏两张图不加 `loading="lazy"`（属于首屏内容，延迟加载反而拖慢 LCP）；下方作品卡的封面才加 `lazy`。
4. 显示尺寸上限 252px（作品卡）/ 259px（首屏），是 640px 素材的 2.5 倍余量，高分屏不糊。

**随之调整的视觉参数**：作品卡封面 216px → 252px，首屏视觉容器 440px → 462px，封面占比 54%/50% → 56%/52%。图片变清晰后，原来的「徽章式」小尺寸反而显得保守，放大后封面才撑得起章节。

> 移动端注意：木筏封面在大屏向外溢出 4%（形成错位层叠），该偏移必须限定在 `min-width:768px` 以上，否则窄屏会被视口裁掉一角。
